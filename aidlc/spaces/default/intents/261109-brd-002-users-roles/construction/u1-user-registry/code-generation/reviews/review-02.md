### What I Verified

The loop-back repair does not weaken the seam test. `services/identity/infrastructure/src/repositories/users.rs` is unchanged from the committed tree and still refuses erasure unless `status IN ('pending_deletion','deleted')`, returning `Conflict`; the new case `the_erasure_guard_refuses_an_account_that_is_not_pending_deletion` asserts that refusal and that the record and protected subject survive it. The repaired seam test drives the stored user to `pending_deletion` through the permitted `active → pending_deletion` edge and the real `UserRepository::update`, then asserts the tombstone contract — `find_by_auth_subject` answers the pseudonymous hash with a `deleted` record, personal fields erased, `reveal_auth_subject` returns `None` — which is the same contract `tests/account_lifecycle_adapters.rs` pins (`find_by_subject_hash` reaches the tombstone; the hash is copied before the personal row leaves). The new adapter cases assert real state changes (hash-collision refusal with counts unchanged, unknown user/key refusals, paging of the due sweep, provision rollback via the `(1,1,1)` counts, every query mapping a dropped schema to `Unavailable`), so they would fail against a wrong implementation. The `config.rs`/`lib.rs` refactor preserves production behaviour: the diff shows identical variable names, defaults and error messages, with the environment read moved behind an injected lookup; `from_env` still performs the real lookups, `run`/`run_worker` still build, bind and serve, and the heartbeat keeps its `/tmp/identity-worker.heartbeat` path. `traceability.json` has 47 upstream IDs matching 47 coverage rows with no gaps or orphans, and every file target exists in the workspace; all 44 paths in `source-manifest.json` exist and include every path this repair touched (`src/config.rs`, `src/lib.rs`, `tests/composition.rs`, `tests/repositories.rs`, the shared harness and `Cargo.toml`). No DTO type reaches inward and no binary floating point is used for values (the only `f64` is the HTTP duration histogram).

### Summary

The repair is genuine and fit to carry into Build and Test: the erasure guard is untouched, the refusal is asserted deliberately, and the new coverage exercises real behaviour through the production router and the real adapters. The two open Majors carried from the earlier review — provider profile changes still not persisted on refresh, and `identity-infrastructure` still at 64.95 % against the 80 % per-crate floor — are the items the person should weigh before approval.
