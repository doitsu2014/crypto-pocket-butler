### Summary

The core read path is well built: delayed-before-live classification, the 24-hour hard bound, unpriced rather than zero, decimal storage, the row-locked shared rate bucket, the per-job claim and lease SQL, the token middleware with 401/403/422/503, and clean crate boundaries all hold, and the unit command passes 137 tests with 16 database tests skipped. Five blocking problems remain: the FX refresh stores the inverse of the direction the read API can serve, so USD-to-base conversions fail; the refresh is sequential rather than the required 4-in-flight; the C11 run executes inline in the API rather than the worker; the Vault definer function can silently return NULL for every provider key; and the traceability omits NFR17 and points several rows at code that does not implement them.
