### Summary

The design is strong on boundaries, copy, accessibility and the audit statements it has to make, and most of its claims about the existing surface check out against the code. Two things must be settled before implementation: the role shown on the admin record is sourced from a stored value that a role change does not update, so the re-read-and-render behaviour the spec promises returns stale data, and the Approvals panel has neither a list route nor the by-id route it cites, leaving FR20.1's "view support grants" unowned.
