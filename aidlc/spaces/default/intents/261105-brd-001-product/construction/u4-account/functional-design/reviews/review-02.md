> R-01 Reviewer note: HoldingSnapshot now requires `observedToken` and makes `assetId` optional, and its constraint states that a spam holding keeps the observed token and has no assetId. The read side still cannot express that row; that is a new finding below.

> R-02 Reviewer note: `priced` and dust are removed from the Account entities and rules, and the design states Account records no price and no dust flag. The remaining `priced` obligation in C5 is a new finding below.

> R-03 Reviewer note: CSV ownership is now settled in the C5 amendment and in the Account component's entity list. The components Entity Ownership table still gives ImportBatch to Ledger, and the C5 open question about CSV ownership is still listed as open in the same contract.

> R-04 Reviewer note: The six SPA routes are recorded as C1 change requests, with `kind`, `venue` and `status` values aligned to the Account model.

> R-05 Reviewer note: A C4 change request adds a supported-chains read, and BR3.1 states that a newly registered chain becomes selectable on the next read with no Account redeploy, so OQ-1 no longer blocks this unit.

> R-06 Reviewer note: BR2.4 and WF7 call the Supabase Auth admin API (C15) directly, and the claim is cleared on rejection, removal and revocation when no verified credential remains. The component catalogue now lists that dependency.

> R-07 Reviewer note: The order is now verify the new key, then swap and destroy the old secret, and a failed replacement leaves the old credential usable. The state of a credential while a replacement key is pending is still unstated: the model defaults `verificationStatus` to `pending` and the state machine starts there, while BR1.4 says no Credential row exists before verification.

> R-08 Reviewer note: SyncRun carries `leaseUntil`, BR4.2 fails a lease-expired run and releases the guard, WF4 step 8 adds the sweep, and BR4.5 plus the state machine give `disconnected` an outgoing transition.

> R-09 Reviewer note: WF1 verifies the key before creating anything, BR1.4 and the Account constraint say no row exists for a rejected key, and the label is explicitly kept by the SPA for the retry.

> R-10 Reviewer note: BR7.2 lists the audited events and the C10 fields, matching the C10 amendment that makes actor, timestamp and context required.

> R-11 Reviewer note: The blanket admin exception is gone; BR1.1 now requires an active, reason-recorded support grant and allows only the metadata read. The check it names does not exist in C3; that is a new finding below.

> R-12 Reviewer note: Both onboarding workflows now start the first sync immediately. No completion deadline is stated, so nothing in this design backs NFR6's under-two-minutes by address and under-ten-minutes by exchange key.

> R-13 Reviewer note: BR4.1 now separates the paths: scheduled returns 409, manual returns 202 with the active run id, and the C11 amendment matches.

> R-14 Reviewer note: The C5 amendment adds `spam` and `lastSyncedAt` to Holding with their meaning stated.

> R-15 Reviewer note: BR7.1 names the `sync_failed` and `key_revoked` alert types and gives the idempotency key; C9 defines both types and requires the key.
