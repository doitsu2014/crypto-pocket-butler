### Summary

The architecture holds where it matters most: the boundaries are clean (`domain`/`application`/`http` separation intact, DTOs map at the boundary, no secret or token reaches a log), the projection is a genuinely closed shape asserted field-by-field, the uniform 403 and the owner-side 200-empty-projection remove the existence oracle, the outbox writes in the same transaction with SKIP LOCKED claims, the gateway buckets on the token hash without evicting the address windows, and the workspace gates (fmt, clippy, 1582 tests) pass exactly as the summary reports. The blocking concern is deployment, not design: the Portfolio service-token seed cannot add `support_metadata` to the already-seeded identity row, so the unit's central read path returns 503 in the real environment until that row is updated; two request-refusal paths also escape the audit rule the spec states for them, and three new production modules of the support path have no test at all.
